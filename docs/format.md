# 工程与运行契约 v1

应用版本 `0.1.1`，工程格式 `1`，包格式 `1`，运行 API `1`。Godot 基线 `4.7.2`。

可编辑目录以 `character.rigpop.json` 为入口，以同目录 `assets/*.png` 为素材。所有素材路径
均为安全相对路径，拒绝绝对路径、父目录穿越与脚本资源；外部图片导入后复制像素数据。

| 字段 | 内容 |
| --- | --- |
| `id`, `name` | 稳定 ASCII 标识与可编辑显示名称 |
| `parts` | 部件与关节数组：ID、父 ID、绑定位置、角度、枢轴、独立 z、可见性与素材 |
| `actions` | 稳定 ID、名称、帧数、FPS、循环、叠加、优先级、冲突规则、移动锁定与关键帧 |
| `bindings` | 按键名、手势与命令；运行实例持有按住、长按和双击计时状态 |
| `game` | 移动速度与碰撞半径，不含地图放置状态 |
| `desktop` | 像素倍率、初始置顶与漫游，不含当前屏幕位置 |
| `palette` | RGB/RGBA 十六进制色板 |
| `modules` | 按模块 ID 分区的扩展配置，未知字段原样保留 |

每个关键帧含 `frame`，可含 `position`、`rotation`、`asset`、`visible`。位置和角度为绑定姿势
上的偏移；向后选择最近的关键帧，采用保持采样。父子变换与 z 排序独立。
`parts[].kind` 可选，默认 `part`；`joint` 表示透明关节节点。关节保留相同变换和父子契约，
使用 1×1 透明 PNG，运行时通过普通层级传播 FK 变换，不依赖编辑器或 Godot Skeleton2D。
重设父节点保留绑定姿势世界变换；已有动画偏移仍相对于新的父节点求值，不自动重烘焙动画。

叠加动作使用独立计时，只替换自身有关键帧的轨道；空轨道不覆盖底层。
`actions[].priority` 默认 `0`，范围 -100～100；`conflict` 默认 `replace`，可为 `reject`；
`lock_movement` 默认 `false`。这些为格式 1 的可选字段，缺失时使用默认行为。
叠加动作的占用范围包含其非空轨道及全部子节点，全身动作占用全部部件。互不冲突的动作
同时执行；冲突时，新动作为 `reject` 或任何冲突动作的优先级更高，则整体拒绝新动作；
否则只替换冲突动作，同优先级采用后触发者。底层待机/行走不参与触发动作的占用仲裁。
按键或 `execute(id)` 触发的动作执行一个周期，完成后移除，底层移动时钟持续推进。
任一活动动作 `lock_movement=true` 时暂停主动移动，结束后恢复仍按住的方向输入。

键盘保存 Godot 键名；鼠标键名为 `MouseLeft`、`MouseRight`、`MouseMiddle`。桌宠适配层
截留右键用于菜单及缩放，游戏适配层仍传递右键绑定。当前缩放和窗口位置只保存在实例内存中。

保存先写带图像内容摘要和素材身份的 PNG，再写临时 JSON，备份上一版 JSON 后完成重命名。
不同部件的独立素材不会因为像素相同而变成同一张可编辑图片。旧 PNG 保留，以便备份可恢复。
另存为拒绝覆盖不同角色 ID 的目录；高版本或损坏工程不会替换当前文档。

历史使用内存快照，最多 60 次。笔画与部件拖动成组。它不是跨会话的版本管理系统。
模型中不存试演状态。未知模块只保留配置，目标能力必须由实际处理器执行。

`game.visual_scale` 可选，范围 0.1～8，缺省为 2；只缩放游戏中显示的角色，不修改碰撞体。
`modules["rigpop.art"].texture_filter` 为 `linear` 时对插画使用平滑采样，其他值及缺省为
`nearest`，保留像素素材的清晰边缘。来源、作者、许可证与完整立绘动画说明也可保存在该模块。

Godot 包包含 `addons/rigpop_runtime/` 中的源码与 `characters/<ID>/` 中的数据/入口场景。
无全局类或自动加载单例，共用目录按运行 API 版本复用。入口的 `character_file` 为可导出的场景属性。
地图实例的位置、队伍与用户脚本应保留在地图自己的节点或场景中。

Windows 桌宠使用预构建宿主与外部 JSON/PNG，不包含编辑 UI、PSD 解析器或游戏控制器。
用户导出无需调用 Godot 编辑器。`RigPopPet.exe` 与 `.pck` 必须保留配套文件名。

`rig` 与 `parts[].role` 是格式 1 的可选字段。内置骨架为 `rigpop.quadruped.v1` 与
`rigpop.biped.v1`；角色中保存的动作仍按部件 ID 引用。复用预设按 `role:` 前缀记录轨道，
套用时映射为目标部件 ID；位置偏移根据 `modules["rigpop.rig"].motion_scale` 换算。

PSD 来源位于 `modules["import.psd"]`：`source` 是来源文件名，`source_file` 是工程内
`sources/<内容摘要>.psd` 的相对路径，`layers` 记录原始图层键、部件 ID 与骨骼角色。
JSON/PNG/PSD 构成完整可编辑工程。普通运行导出移除 `source_file` 并排除 PSD，保留来源映射。
Windows 原生扩展 `rigpop_windows.dll` 是桌宠运行依赖，应与 EXE 一起分发。
保留 `platform/windows/bin/rigpop_windows.dll` 的相对层级；扩展描述文件按此路径加载原生库，
不能只保留导出器同时复制到 EXE 旁边的库副本。
